מקרא הצבעים

  • מה שהמשתמש רואה ונוגע בו (הלוח, VS Code)
  • תוכנה שרצה (אתר, Realtime, ראנר, מנועי האייג'נטים)
  • נתונים (טבלאות בענן, תיקיות עבודה בדיסק)
  • שער ובקרה (התחברות, הגדרות שקובעות מה מותר)
  • חשבונות AI חיצוניים

חץ רציף = בקשה או שליחה. חץ מקווקו = תשובה שחוזרת (לולאת המשוב: התוצאה עולה לתור, ו-Realtime מביא אותה ללוח).

הסבר קצר

הרכיבים

  • הלוח - אתר סטטי (HTML ו-JavaScript) ש-GitHub Pages מגיש. הוא לא מריץ כלום במחשב: הוא רק קורא וכותב ל-Supabase.
  • Supabase - הענן היחיד באמצע. התחברות, ושלוש טבלאות: המסמך עם כל המשימות, התור של ההודעות לאייג'נטים והתשובות שלהם, ורשימת המחשבים. Realtime משדר כל שינוי מיד לכל מי שמחובר. כל משתמש רואה רק את השורות שלו (RLS).
  • הראנר - תוכנית Node קטנה שרצה ברקע בכל מחשב פיתוח. היא מתחברת לאותו חשבון של הלוח, לוקחת רק הודעות שמיועדות למחשב שלה, ומפעילה את המנוע.
  • המנוע - Claude Code או Codex, אותם כלים שעובדים איתם ידנית, רק בלי מסך. כל אחד מחובר לחשבון של הפרופיל שלו, ושולח את הקוד והשיחה לספק ה-AI של אותו חשבון.
  • תיקייה וענף לכל משימה - העותק שהאייג'נט עובד בו (git worktree), ליד תיקיית הפרויקט ולא בתוכה. משם עוברים על העבודה ב-VS Code וממזגים ידנית.

מסלול של הודעה אחת

  1. בלוח שולחים תת-משימה לאייג'נט. שורה חדשה נכנסת לתור: לאיזה מחשב, איזה פרויקט, איזו תת-משימה, והטקסט. תת-המשימה עוברת ל"ממתין לתגובה".
  2. הראנר של אותו מחשב שומע על השורה (Realtime, ובנוסף בדיקה כל 15 שניות), תופס אותה ומסמן "עובד".
  3. הראנר מכין את התיקייה והענף של המשימה, ומעביר את ההודעה למנוע של הפרופיל, עם החשבון של הפרופיל.
  4. המנוע עובד: קורא ועורך קבצים בתיקייה, ומדבר עם ספק ה-AI שלו.
  5. הראנר כותב לתור את התוצאה: סטטוס, סיכום, ענף ומספר קבצים שהשתנו. הפירוט המלא נשאר בלוג במחשב.
  6. Realtime מביא את התוצאה ללוח. תת-המשימה עוברת ל"בעבודה אצלי", והתשובה מופיעה בחלון האייג'נט. אפשר לענות, וההודעה הבאה ממשיכה את אותה שיחה.

ההפרדה בין עבודה לאישי

  • פיזית: כל עולם רץ במחשב משלו. קוד העבודה והחשבונות של העבודה לא נמצאים במחשב האישי, וההתחברות האישית לא נמצאת במחשב העבודה.
  • בהגדרות: כל ראנר מכיר רק את הפרויקטים שלו, ודוחה הודעה לפרויקט אחר. ההודעה מהלוח מציינת רק מחשב ומפתח פרויקט, לא נתיב ולא חשבון.
  • נקודת המפגש היחידה: הלוח וה-Supabase שלו משותפים, ולכן טקסט המשימות של העבודה נשמר בפרויקט האישי.

כשמחשב כבוי

  • אחרי 3 דקות בלי דיווח הלוח מציג אותו "לא מחובר". הלוח עצמו ו-Supabase ממשיכים לעבוד.
  • אפשר להמשיך לשלוח לפרויקטים שלו, גם מהנייד: ההודעות מחכות בתור, והראנר מריץ אותן לפי הסדר כשהמחשב עולה.
  • הודעה שהייתה באמצע עבודה מסומנת "נכשל" כשהראנר עולה שוב. התיקייה, הענף והשיחה נשמרים.

המצב בקוד היום: כל פרויקט משויך למנוע אחד. במחשב העבודה אפשר להחזיק את Claude ואת Codex בפרופילים נפרדים, אבל לפרויקטים שונים.
